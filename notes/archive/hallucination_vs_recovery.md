# Hallucination vs Genuine Recovery: Investigation Plan

## The Question
MSE cond achieves 0.992 per-cell corr (imputed nuc vs cell-type mean), far above the 0.843 baseline (real cell vs own ct mean). But imputed nuc vs raw nucleus drops to 0.585. Is the model:
- (A) Genuinely recovering per-cell expression from nucleus data, or
- (B) Collapsing to cell-type means with little per-cell variation?

## Architecture Context
The conditioned decoder has two information sources:
1. **z (latent)** — per-cell, from shared encoder
2. **Modality embedding** — fixed vector, same for all cells of one modality (0=cell, 1=nuclei)

If the model collapses to means, z only encodes cell-type identity and the decoder uses modality embedding to select which modality's mean to output. Per-cell variation in z is ignored.

## Proposed Tests

### Category A: Output-level tests (do imputed profiles have per-cell variation?)

**A1. Per-cell variance test** (EASY, FAST)
- Compare Var(imputed nuclei | cell type) vs Var(real cells | cell type)
- If ratio ≈ 0, model collapses to means
- Per-gene: compute variance within each cell type for imputed vs real

**A2. Within-cell-type ranking preservation** (EASY, FAST)
- For each cell type + gene, compute Spearman correlation between raw nuclei expression and imputed nuclei expression
- If model preserves within-CT variation, this should be positive
- If it collapses to means, this will be ~0

**A3. Held-out gene test** (GOLD STANDARD, but requires retraining)
- Train on subset of genes, impute all genes, check held-out gene performance
- If model genuinely recovers per-cell patterns, held-out genes perform above cell-type mean
- Future work — mention as definitive test

**A4. Paired data test** (CONCEPTUAL, no paired data available)
- Would need matched cell-nucleus pairs from same biological sample
- Allen Brain Atlas doesn't have this
- But: could simulate by splitting cell data into "pseudo-nucleus" (subsample reads) and test recovery

**A5. The 0.585 nuc correlation decomposition**
- How much of the 0.585 imputed-vs-raw-nuc correlation is cell-type identity vs within-CT signal?
- Compute: corr(imputed, raw_nuc) within each cell type separately
- If within-CT corr > 0, model retains per-cell info from the nucleus

### Category B: Mechanism-level tests (what does each component contribute?)

**B1. z ablation — replace z with cell-type mean z** (FAST, MOST DIRECT)
- For each cell type, replace every nucleus's z with the cell-type mean z
- Decode with cell embedding
- If output barely changes → decoder ignores per-cell z variation
- Compare: Var(output | original z) vs Var(output | mean z)

**B2. z variance decomposition** (FAST)
- Compute fraction of z variance that is between-CT vs within-CT
- ANOVA-like: SS_between / SS_total for each latent dimension
- If between-CT variance dominates (>90%), z is mostly encoding cell-type labels

**B3. Modality embedding swap** (FAST)
- Same nucleus z, decode with cell embedding vs nuclei embedding
- The difference = what the modality embedding contributes
- Quantify: how much of the cell-vs-nuclei translation comes from embedding alone?

## Priority Ranking for Tomorrow's Talk

### Must-do (definitive, fast, no retraining):
1. **A1 (variance test)** + **B1 (z ablation)** — together they answer: does the decoder use per-cell info from z?
   - If imputed variance ≈ 0 AND z-ablation doesn't change output → confirmed collapsing to means
   - If imputed variance > 0 AND z-ablation changes output → genuine per-cell recovery
2. **A2 (within-CT ranking)** — complementary to A1, tests whether gene-level rankings are preserved

### Should-do (enriches the story):
3. **A5 (0.585 decomposition)** — decomposes the nuc correlation into CT-identity vs per-cell
4. **B2 (z variance decomposition)** — shows how much of latent space is CT-identity vs individual
5. **B3 (modality embedding swap)** — shows what the embedding contributes (nice mechanistic slide)

### Future work (mention only):
6. **A3 (held-out genes)** — requires retraining, gold standard for genuine recovery
7. **A4 (paired/simulated data)** — could simulate with read subsampling

## Implementation Notes
- Tests A1, A2, A5, B1, B2, B3 all only need forward passes through the trained model
- Can reuse the imputed data already generated by comprehensive_eval.py
- B1 needs encoder output (z vectors) — need to save these during forward pass
- B2 also needs z vectors
- B3 needs decoder forward pass with swapped embedding
- Estimate: single script, ~30 min on GPU node
